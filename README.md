# 새농 · 매출과 이익

가락·야탑·동천의 매출, 매출총이익, 마진, 월 매출 목표, 카테고리별 추이와
농할·수산대전·임산부 프로모션 할인을 보여주는 조회 전용 웹 애플리케이션입니다.
일반 사용자는 웹사이트만 조회하며 파일 업로드나 수정 기능은 제공하지 않습니다.

자동 갱신을 위한 상시 운영 패키지와 남은 외부 연결 사항은 [OPERATIONS.md](OPERATIONS.md)에 정리했습니다.
Docker 서비스, 개인용 접속 인증, 5분 간격 화면 갱신, 매일 08:00 수집·09:00 백업을 지원합니다.
실제 운영 서버 연결과 데이터 이관·정시 실행·서버 밖 백업 검증은 아직 완료하지 않았습니다.

## 우선 본인만 화면을 보는 방법

환경 게시나 공개 서버 없이도 브라우저에서 월 선택·차트·표를 볼 수 있는
**개인용 HTML 저장본**을 지원합니다. Python 설치나 ATPOS 로그인이 필요 없습니다.
전달된 `saenong-dashboard.zip`을 풀고 `새농.html`을 Chrome 또는 Edge에서 열어
별도로 전달받은 열기 암호를 입력합니다. 이 암호는 ATPOS 로그인 암호와 다릅니다.

이 파일은 저장 시점의 자료이며 **매일 자동으로 갱신되지 않습니다.**
화면에 저장 시각과 각 보고서 기준일을 표시합니다. 원본 불일치로 보류한 마진도 그대로 보류합니다.
자동 수집 프로그램과 원본 보관은 유지하며, 개인용 화면 전달에 환경 게시 성공을 요구하지 않습니다.

실제 매출이 담긴 원본 HTML과 열기 암호는 저장소 밖에 보관합니다.
전달용 ZIP에는 AES-256-GCM으로 암호화된 HTML 하나만 넣으며,
ATPOS 인증 정보·고객별 원본·데이터베이스·열기 암호를 넣지 않습니다.

개발자가 자료를 갱신하고 전달용 파일을 만드는 명령은 다음과 같습니다.

```sh
python -m saenong.offline --data-dir /private/saenong --output /private/saenong/delivery/saenong.html
python tools/package_viewer.py --source /private/saenong/delivery/saenong.html --output /private/saenong/delivery/saenong-dashboard.zip --password-file /private/saenong/viewer-password.txt --executable /usr/bin/chromium
python tools/check_offline.py --archive /private/saenong/delivery/saenong-dashboard.zip --password-file /private/saenong/viewer-password.txt --data-dir /private/saenong --executable /usr/bin/chromium
```

포장은 기존 Playwright와 브라우저 Web Crypto를 사용합니다. 파일을 보는 사람에게는 브라우저만 필요합니다.
합성 매출로 전체 전달 과정을 검사하는 `python tools/check_personal.py`를 Windows·Linux CI에 포함했습니다.
이 개발 환경의 관리 정책은 `file://` 열기를 막으므로, 여기서는 같은 문서를 Blob으로 열고
인터넷과 초기화 서버를 모두 끈 뒤 검사합니다. 직접 파일 열기 검사는 이 환경에서 미실행이며,
CI 실행 결과와 구분합니다.

## 현재 검증 범위

실제 ATPOS 로그인과 세 매장의 월별 손익·일별 매출·프로모션 요약·상세 다운로드를 검증했습니다.
설정한 비밀값을 HTTPS POST 본문으로 전달하고 세션을 사용하므로,
개발 중에 사용자가 PC에 내려받아 로그인이나 파일 다운로드를 시험할 필요가 없습니다.
원본의 합계, 데이터 교체·이력 보존, 계산, API, PC·모바일 표시를 검사합니다.
실제 인터넷 공개 배포와 다음 날 정시 실행은 별도 운영 검증 대상입니다.

## 계산 기준

- 총매출 = 순매출 + **할인액**. 손익표의 `총할인`에는 조정·폐기 영향이 섞여 있어 사용하지 않습니다.
- 매출원가 = 기초재고 + 순매입 − 기말재고
- 매출총이익 = 총매출 − 매출원가
- 마진율 = 매출총이익 ÷ 총매출 × 100. 총매출 0원이면 계산하지 않습니다.
- 월 매출 목표는 전년 대비 가락·야탑 5%, 동천 10% 성장입니다.
  1·2월 및 9·10월은 각각 전년 두 달 총매출 평균에 성장률을 적용합니다.
  전년 기준 월의 전체 자료가 없으면 목표는 미계산으로 둡니다.
- 마진 목표: 가락·야탑 18.5%, 동천 16.5%.
- 월별 손익은 선택 월 기준이며 당월은 MTD 잠정값입니다. YTD 차액을 계산하지 않습니다.
  진행 중인 달의 누적값은 차트에서도 별도로 표시하고 일별 추이는 전일까지 보여줍니다.
- 할인·취소·반품·부가세·폐기는 원본에 반영된 것으로 보고 추가 조정하지 않습니다.
- 프로모션 요약의 고객별 할인을 집계하고 품목별 할인과 대조합니다. 상세 자료를 다시 합산하지 않습니다.
- 음수는 보존합니다. 원본이 명시적으로 '해당 매출이 없습니다'라고 확인한 날짜만 0원으로 처리합니다.
  설명 없이 비어 있는 금액이나 수집하지 못한 자료를 0원으로 바꾸지 않습니다.

## 누락을 막는 조회 조건

월별 손익은 **본부종합(check_yn=5)**으로 조회합니다.
'본사 사용 품목'은 현재 미사용인 상품의 과거 판매를 제외하여 과거 매출이 누락됐고,
본부종합으로 조회하면 일별 매출표의 합계와 일치하는 것을 실제 자료로 확인했습니다.
보고서 종류·매장·월·기준일·실제 조회 조건과 원본을 함께 기록합니다.
월별 보고서에는 일 단위 종료 조건이 없으므로 당월 자료를 전날 마감값으로 잘못 표시하지 않습니다.

실제 내보내기는 `.xls` 확장자의 CP949 HTML 표입니다. 행·열 병합을 해석하고 상세 행과
전체 합계를 대조합니다. 재고 표시금액에는 원본의 상품별 정수 합계와 전체 합계 차이가 발생할 수 있습니다.
그 차이가 상품당 1원 이하 범위이면 전체 지표는 원본 전체 합계를 사용하고 정확한 차이를 경고합니다.
상품별 값을 임의 조정하지 않으며, 그 밖의 파일 내부 금액 불일치는 반영하지 않습니다.
닫힌 월의 일별·월별 총매출이 다르거나 전체 상품 범위를 확인하지 못한 경우에는
검증된 일별 보고서의 매출만 표시하고 이익·마진과 해당 카테고리 손익을 보류합니다.
매출 목표는 검증된 전년 매출을 기준으로 계산하며, 서로 다른 원본을 임의로 보정하지 않습니다.

## 자동 수집

Python 3.11 이상이 필요합니다. 수집과 웹 앱은 기본 라이브러리만 사용합니다.
환경 설정의 비밀 인증 연결은 `ATPOS_ID`, `ATPOS_PASSWORD`, 허용 목적지는 `www2.atpos.co.kr`입니다.
값을 코드·채팅·설치 스크립트에 넣지 않습니다. 프록시 인증 연결을 로컬 원시 비밀번호라고 가정하지 않습니다.
로그인 자격 증명을 URL에 넣지 않으며 인증 요청·쿠키 값도 출력하지 않습니다.

```sh
# 전월과 당월, 세 매장, 보고서 네 종류를 한 번 수집
python -m collector.run --data-dir /private/saenong

# 과거 월별 손익/일별 매출/프로모션 요약 수집. 완료된 과거 자료는 재사용
python -m collector.run --data-dir /private/saenong --from-month 2024-01 --through-month 2026-09 --kinds monthly-profit daily-sales promotion-summary --skip-existing

# 실제 ATPOS 대분류 필터로 상품/소분류 연결을 갱신
python -m collector.categories --data-dir /private/saenong --period 2026-10

# 매일 오전 8시 한국 시간에 실행하는 작업 프로세스
python -m collector.schedule --data-dir /private/saenong --hour 8
# 당일 수동 검증을 마친 경우 즉시 중복 조회를 피하고 다음 정시까지 대기
python -m collector.schedule --data-dir /private/saenong --hour 8 --no-catch-up
```

예약 작업은 실행 시간과 중복 시도 방지를 테스트하며, 실제 수집 작업도 별도로 실행해 검증합니다.
다음 날 정시 실행까지 이미 확인했다고 주장하지 않습니다. 인증 실패를 변경 없이 반복 재시도하지 않습니다.
운영 시에는 서비스 관리자로 웹 서버와 수집 작업을 각각 시작하고 종료·장애 시 재시작해야 합니다.
클라우드 스냅샷은 파일을 보존하지만 실행 중인 프로세스는 보존하지 않습니다.

매일 전월도 다시 받아 마감 후 정정을 반영합니다. 실패 시 이전 검증 자료는 유지합니다.
같은 파일은 이중 집계하지 않고, 정정 파일은 해당 월/매장/보고서의 활성 자료를 대체합니다.
이력과 해시별 원본을 보관합니다. 수집 결과는 `collection-status.json`에 기록합니다.
프로모션 자체가 없는 기간은 '자료 없음'으로 구분하며 없는 보고서를 통과한 검사로 세지 않습니다.

## 카테고리

상품의 실제 대분류를 조회해 정육/냉장, 과일/채소, 상온/냉동으로 연결하며,
본부종합 전체 상품에서 이 세 대분류를 뺀 나머지는 기타로 묶습니다.
따라서 현재 선택 목록에서 사라진 과거 대분류도 누락하지 않습니다.
데이터 폴더의 `product-categories.json`은 상품코드 기준이며 `categories.json`은
여러 대분류에 걸치지 않는 것으로 확인된 소분류 기준 보완 자료입니다.
근거 조회 정보는 `category-sources.json`에 남깁니다. 확인되지 않은 항목은 미분류로 표시합니다.

## 웹 앱

```sh
python -m saenong.server --data-dir /private/saenong --port 8000
```

외부 공개는 운영용 HTTPS 프록시와 서비스 관리자를 구성한 뒤 별도로 검증해야 합니다.
현재 명령만 실행한 상태를 인터넷 공개 배포 완료로 간주하지 않습니다.
조회 API와 화면만 서비스하며 원본·SQLite·로그인 세션은 HTTP로 제공하지 않습니다.
분석 저장 자료에는 고객명·고객번호·카드번호·영수증번호를 넣지 않습니다.
원본에는 개인정보가 있으므로 코드 폴더 밖의 비공개 경로에서 보관·접근 통제·백업합니다.
매출 원본, 평문 매출 데이터, 인증 연결, 로그인 세션은 GitHub에 올리지 않습니다.
개인용 화면을 전달할 때는 위의 암호화된 ZIP만 사용할 수 있으며, 열기 암호는 함께 저장하지 않습니다.

외부에서 받은 파일을 개발자가 검증해 가져오는 명령도 지원합니다.

```sh
python -m saenong FILE.xls --data-dir /private/saenong --store 가락 --period 2026-10 --as-of 2026-10-21
```

## 개발 검증

```sh
python -m unittest discover -s tests -v
python -m pip install -r requirements.txt
python -m playwright install chromium
python tools/check_browser.py
```

비공개 데이터 화면 검증에는 `--data-dir`, 이미 설치된 Chromium에는 `--executable`을 지정합니다.
브라우저 검증에서 TLS 검증을 끄지 않습니다. 클라우드 환경 CA와 인증서 저장소 접근이 필요할 수 있습니다.
GitHub Actions에 Windows·Linux 검사를 등록했으며 실제 완료 결과는 별도로 확인해야 합니다.
기존 `START.cmd`와 수동 브라우저 수집기는 개발용 보조 도구이며 일반 사용자의 설치 절차가 아닙니다.
